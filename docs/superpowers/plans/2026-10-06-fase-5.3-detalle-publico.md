# Fase 5.3 — Detalle público de actividades

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permitir abrir una actividad pública desde la agenda o por URL directa, mostrando programa, unidad, ponentes, aula, horario, capacidad y estado, sin tocar el modelo administrativo ni la caché privada.

**Architecture:** El puerto público gana `getPublicActivity(id)` con un modelo y mapper propios; el hook usa una clave `public-activity-detail` no persistida. La página es delgada y la vista conectada consume el hook. Una cancelada muestra aviso y motivo; un borrador o programa no público se presenta como no disponible.

**Tech Stack:** React 19, TypeScript, React Router 8, TanStack Query 5, Chakra UI 3, Vitest, Storybook 10.

---

## Contrato y alcance

- `GET /api/v1/activities/{id}`: público; anónimos solo ven actividades no borrador de programas activos; ADMIN o colaborador con `activity:read` pueden leer borradores y programas no activos, pero la vista pública NUNCA los expone: si el payload llega con `DRAFT`, se trata como no disponible.
- El detalle expone `cancelReason`, `enrolledCount`, `checkedInCount` y `equipment`; el modelo presentará `cancelReason` y `enrolledCount`, y validará el DTO completo para detectar drift sin exponer equipamiento.
- 404 (y DRAFT) → estado vacío `null` → “Actividad no disponible”. Errores 5xx/red → fallo con reintento.
- La consulta es idéntica con o sin sesión, sin cookies ni Bearer, y no se persiste.

**Ruta:** `/actividades/:activityId` dentro del layout público.

## Evidencia de cierre — 2026-10-06

- **Modelo y mapper (Tarea 1):** `PublicActivityDetail` valida el DTO completo (incluye `equipment` y `checkedInCount`) pero solo proyecta lo presentado; `cancelReason` requerido-nullable; `DRAFT` lanza error de mapping porque es drift de contrato y la vista pública jamás lo expone.
- **Puerto y adapters (Tarea 2):** `getPublicActivity(id)` hace una sola petición con id codificado, sin `Authorization` y con `credentials: "omit"`; `404 → null`; el mock devuelve null para inexistente, DRAFT o programa no activo, y sí para canceladas con motivo.
- **Hook (Tarea 3):** `usePublicActivityDetail` deduplica por id, no reutiliza el detalle anterior al cambiar de actividad, no se persiste (`public-activity-detail` fuera de `PERSISTED_QUERY_KEY_ROOTS`) y un fallo público no toca la sesión.
- **Vista y recorrido (Tareas 4–5):** `PublicActivityDetailView` presenta estado, programa, unidad, ponentes, aula, horario, capacidad/inscritos/disponibles y el aviso de cancelación con motivo; cubre carga, error con reintento y "Actividad no disponible". La tarjeta enlaza el nombre al detalle y `/actividades/:activityId` queda registrada sin guard de sesión; el mismo resultado aplica a USER, ADMIN y colaborador.
- **Puertas verdes:** `verify:quick` (209 archivos, 1574 pruebas), `storybook:test:affected` (10/10 del detalle y tarjeta) más las 8 de filtros de 5.2, `components:inventory:check` y `api:mocks-check` (356 verificaciones).
