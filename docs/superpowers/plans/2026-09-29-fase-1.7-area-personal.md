# Fase 1.7 Area Personal Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan
> task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Convertir `/perfil` en el unico destino personal de cualquier rol autenticado, agregando la
seccion de seguridad y los accesos informativos a las areas personales futuras, y asegurar que un
`USER` termine siempre en su area personal y nunca en una pantalla administrativa.

**Architecture:** `/perfil` sigue siendo una pagina de composicion delgada que reusa `ModuleShell`,
`SectionHeader` y `Surface` del catalogo compartido; el formulario conectado no se toca y sigue siendo
`ProfileView`. La seguridad no se reimplementa: la seccion nueva solo ofrece una entrada al flujo ya
existente `/cambiar-contrasena`. Los servicios personales de fases 9 y 10 se anuncian como tarjetas
informativas sin enlaces, botones ni controles deshabilitados, porque sus rutas no existen y la ruta
comodín las convertiria silenciosamente en un callejon sin salida. La regla de destino por rol vive en
una funcion pura unica, `resolveAuthLandingPath`, que consumen tanto `LoginPage` como el guard
administrativo.

**Tech Stack:** React 19, TypeScript 6, Vite 8, Chakra UI 3, React Router 8, Zustand 5, Vitest 5,
Testing Library, Storybook 10.

**Estado:** ejecutado el 2026-09-29. Las 41 casillas quedaron verificadas y `pnpm run check` termino en
verde con 592 pruebas unitarias, 88 suites de Storybook sin violaciones de accesibilidad y 88 baselines
visuales en verde.

## Por Que No Se Consulta OpenAPI

Esta fase no introduce, modifica ni elimina ninguna peticion HTTP. Reutiliza `ProfileView`,
`useProfile`, `useRegistrationCatalog` y el flujo `POST /api/v1/auth/change-password` tal como los
verifico la Fase 1.5 y la Fase 1.6 contra el backend vivo. No se crean puertos, DTO, mappers, mocks ni
query keys, por lo que `pnpm run api:mocks-check` no aplica: no hay contrato nuevo que derivar.

## Decisiones

- **Composicion de seguridad:** resumen con llamada a la accion dentro de `/perfil`, no formulario
  embebido. El formulario ya tiene su propio estado de mutacion, su localized copy de errores y sus
  pruebas; embebberlo duplicaria el estado de exito y las dos rutas podrian divergir.
- **Servicios futuros:** tarjetas informativas. Un enlace a `/mis-actividades` o `/mis-certificados`
  caeria en `<Route path="*">` de `App.tsx` y redirigiria a `/`, que es exactamente el callejon sin
  salida que 1.7 debe evitar. Un control deshabilitado no es alcanzable con teclado ni anunciable con
  usefulness, asi que tampoco se ofrece.
- **Menu:** "Cambiar contrasena" sale de `AppMenu` para que "Mi perfil" sea el unico destino personal.
  La ruta `/cambiar-contrasena` no se elimina: sigue registrada, sigue protegida por `RequireSession` y
  sigue funcionando por enlace directo, como exige la arquitectura de informacion.
- **Jerarquia de encabezados:** `h1` de `ModuleShell`, `h2` por seccion y `h3` en cada tarjeta. La
  seccion de datos personales no recibe un `SectionHeader` propio porque `ProfileForm` ya presenta su
  propio `h2` ("Mantenga sus datos al dia"); anadir otro duplicaria el encabezado.
- **Copy:** español con acentuacion completa, igual que `ChangePasswordPage` y `ProfileForm`. Las
  pruebas usan clases de caracteres (`/[aá]rea/`, `/contrase[nñ]a/`) para ser insensibles a la tilde.
- **Sin story de pagina.** El catalogo de Storybook del proyecto cubre `Shared/UI`, `Layout` y
  `Features`; ninguna pagina tiene story y la taxonomia no tiene seccion `Pages`. La composicion nueva
  es privada y de un solo uso, lo que `AGENTS.md` permite permanecer local al padre. Se cubre con
  `src/pages/ProfilePage.test.tsx`, igual que `ChangePasswordPage.test.tsx`.

## Sin Commits

incluye `git commit`. El arbol de trabajo ya contiene trabajo sin commitear de las fases 1.4 a 1.6; se

import type { GlobalRole } from "@/types/domain";

/**
 * Resolves the destination that matches the authenticated global role. Administrators continue in the
 * operational panel; every other role lands on the personal area, so a standard user never reaches an
 * administrative screen, neither after login nor through a rejected guard.
 */
export function resolveAuthLandingPath(globalRole: GlobalRole): "/admin" | "/perfil" {
  return globalRole === "ADMIN" ? "/admin" : "/perfil";
}

  1.5 y no contenia "Mi perfil", pero la comparacion visual lo daba por correcto. Hay dos causas que se
  refuerzan: `maxDiffPixelRatio: 0.01` tolera la diferencia entre ambos menus, y `--update-snapshots`

  Se elimino el archivo y se regenero; la captura ya muestra "Mi perfil" mas "Cerrar sesion". Las

  en la captura.

  seccion de seguridad se vio que el componente compartido renderiza el mensaje crudo. Es un

  use, asi que queda reportado para 1.8 o 1.9 en lugar de ampliar el alcance de 1.7.
