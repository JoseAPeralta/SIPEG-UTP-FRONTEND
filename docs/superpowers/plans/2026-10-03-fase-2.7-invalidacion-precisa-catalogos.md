# Fase 2.7 Invalidacion Precisa De Catalogos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Que cada mutacion de unidades, carreras y aulas refresque exactamente los listados, detalles, formularios y selectores que dependen de ella, demostrando la actualizacion sin recargar la aplicacion.

**Architecture:** Las mutaciones invalidan prefijos centralizados de TanStack Query, ligados a la identidad (`userId`) y nunca al token; la frontera publica y la administrativa nunca se mezclan. Cada comando declara su propia matriz de dependencias y devuelve la promesa de invalidacion para que la mutacion siga pendiente hasta que terminen los `refetch` activos.

**Tech Stack:** React 19, TypeScript 6, TanStack Query 5, Vitest 5 y Testing Library.

---

## Contrato y alcance

- **Sin cambio contractual:** la fase no introduce, modifica ni elimina ninguna operacion HTTP, campo, adapter ni mock. No se consulta OpenAPI y no aplica `api:mocks-check`.
- **Sin cambio visual:** no se tocan componentes, stories ni baselines. El unico cambio de UI es de comportamiento observable en pruebas.
- Se centralizan las raices que hoy se escriben como arrays literales en los hooks de mutacion.
- La matriz de aulas se separa por tipo de cambio (resumen, amenidades, horario) en lugar de invalidar todo en cada comando.

## Matriz de invalidacion objetivo

| Mutacion                      | Listas                      | Detalle exacto                                 | Actividades publicas               | Actividades admin             | Disponibilidad |
| ----------------------------- | --------------------------- | ---------------------------------------------- | ---------------------------------- | ----------------------------- | -------------- |
| Crear unidad                  | publica + admin (identidad) | no                                             | no                                 | si (programa predeterminado)  | no             |
| Editar unidad                 | publica + admin (identidad) | publica + admin (misma unidad)                 | solo si cambia `name`              | no (recompone desde la lista) | no             |
| Desactivar/reactivar unidad   | publica + admin (identidad) | publica + admin (misma unidad)                 | si (programa archivado)            | si                            | no             |
| Crear/editar/eliminar carrera | publica + admin (identidad) | detalles de unidad publica + admin (identidad) | no                                 | no                            | no             |
| Crear aula                    | publica + admin (identidad) | no                                             | no                                 | no                            | si             |
| Editar aula                   | publica + admin (identidad) | publica + admin (misma aula)                   | solo si cambia `name` o `building` | no                            | si             |
| Agregar/quitar amenidad       | publica + admin (identidad) | publica + admin (misma aula)                   | no                                 | no                            | si             |
| Agregar/quitar horario        | no                          | publica + admin (misma aula)                   | no                                 | no                            | si             |

```ts
import { describe, expect, it } from "vitest";

import { queryKeys } from "./queryKeys";

function isPrefix(prefix: readonly unknown[], key: readonly unknown[]): boolean {
  return prefix.every((part, index) => key[index] === part);
}

describe("queryKeys prefixes", () => {
  it("should match every availability criteria from one root", () => {
    const key = queryKeys.availableClassrooms({
      date: "2026-08-24",
      endTime: "11:00",
      startTime: "09:00",
    });

    expect(isPrefix(queryKeys.availableClassroomsRoot, key)).toBe(true);
  });

  it("should match every public unit detail from one root", () => {
    expect(
      isPrefix(
        queryKeys.publicOrganizationalUnitDetails,
        queryKeys.publicOrganizationalUnitDetail("fisc"),
      ),
    ).toBe(true);
  });

  it("should scope administrative unit details to one identity", () => {
    const scoped = queryKeys.administrativeOrganizationalUnitDetails("user-1");

    expect(
      isPrefix(scoped, queryKeys.administrativeOrganizationalUnitDetail("user-1", "fisc")),
    ).toBe(true);
    expect(
      isPrefix(scoped, queryKeys.administrativeOrganizationalUnitDetail("user-2", "fisc")),
    ).toBe(false);
  });

  it("should scope administrative classroom lists by identity across filters", () => {
    const scoped = queryKeys.administrativeClassroomsScope("user-1");

    expect(
      isPrefix(scoped, queryKeys.administrativeClassrooms("user-1", { type: "CLASSROOM" })),
    ).toBe(true);
    expect(
      isPrefix(scoped, queryKeys.administrativeClassrooms("user-2", { type: "CLASSROOM" })),
    ).toBe(false);
  });

  it("should keep the public detail root out of the administrative boundary", () => {
    expect(
      isPrefix(
        queryKeys.publicOrganizationalUnitDetails,
        queryKeys.administrativeOrganizationalUnitDetail("user-1", "fisc"),
      ),
    ).toBe(false);
  });
});
```
