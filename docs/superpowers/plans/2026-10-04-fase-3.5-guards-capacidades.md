# Fase 3.5 - Guards y navegación por capacidades

> **Para agentes:** usar `executing-plans` y TDD; ejecutar cada checkbox como un paso verificable.

**Goal:** descubrir trabajo autorizado y proteger rutas operativas por scope sin abrir la administración institucional.

**Architecture:** `useUserScopes` es la fuente de descubrimiento; permisos efectivos, no roles inferidos, deciden los accesos. El área operativa carga de forma diferida y nunca consume el agregado global `OperationsAdapter`.

**Tech Stack:** React, TypeScript, Chakra UI, React Router, TanStack Query, Vitest y Storybook existentes.

## Ejecución y propiedad

Plan aprobado por la petición de ejecución del usuario. El usuario eligió ejecución directa al no existir runtime local de IA compatible con el sandbox. En una ejecución paralela, el trabajador A posee capabilities, guards, vista de scopes y layout operativo; el coordinador posee App, AppMenu, claves Query, composition roots, catálogo y documentación compartida. B (3.6) y C (3.7) trabajan sobre módulos separados.

## Criterio de salida

Solo se habilitan scopes efectivos de la identidad actual. Un scope no concede acceso horizontal a otro. Usuarios, aulas, unidades y carreras permanecen ADMIN. Los módulos futuros no muestran operaciones simuladas.

## Evidencia y decisiones de cierre

- `OperationalScopeView` contiene el guard exacto y confirma permisos propios antes de componer PII;
  no se creó un wrapper adicional `RequireScopeCapability` sin otro consumidor.
- El contexto operativo vive en la URL. El selector consume descubrimiento, no `useWorkingContext`
  ni el catálogo administrativo. Las rutas institucionales y sus aliases mantienen ADMIN.
- El menú carga su enlace de operaciones de forma diferida. Los hooks usan `adapters/context` y
  `query/keys`, evitando que el enlace arrastre composition roots síncronos o mocks.
- Los límites temporales tienen un timer por frontera, sin polling de render. Una prueba adelanta
  el reloj y demuestra que el permiso vence sin esperar otra respuesta HTTP; las consultas propias
  y de descubrimiento también se refrescan cada minuto.
- Iteración con Vitest dirigido para no expandir reiteradamente el grafo de importadores desde App;
  `test:related` sí se ejecutó para 3.7 y luego `verify:quick` y `check` recorrieron todas las pruebas.
- Puerta final `pnpm run check`: **169 archivos / 1114 pruebas**, build, **152 play**, **152 axe y
  comparaciones visuales**, inventario de **44 componentes**, todos verdes. `api:mocks-check`:
  **292 verificaciones en 41 entradas de operación**.
- Se revisaron capturas a 320 px y zoom 200 % de scope, conflicto, permisos y selector, sin
  desbordamiento horizontal. Los controles nuevos de colaboración tienen mínimo 44 px.
- Dos baselines de AdminLayout conservaban menús viejos y pasaban por tolerancia de 1 %; se
  regeneraron explícitamente con `--update-snapshots=all`, sin cambiar esa tolerancia global.
- Los módulos de programas/actividades/asistencia/propuestas/certificados/reportes se conectarán en
  sus fases: esta entrega establece su frontera de scope, no consume el agregado transitorio.
