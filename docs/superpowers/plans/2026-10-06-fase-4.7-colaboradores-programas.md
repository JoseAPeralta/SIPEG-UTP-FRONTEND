# Fase 4.7 — Colaboradores de programas

> **Ejecución:** `executing-plans` con subagentes por bloque, TDD y revisión entre integraciones.

**Objetivo:** integrar la gestión de colaboradores de Fase 3 dentro del panel administrativo de
programas, con consulta de archivados, aislamiento entre programas y recuperación ante errores.

**Arquitectura:** `EventProgramsView` compone `CollaboratorsView`; colaboración conserva sus hooks,
adapters, permisos e invalidaciones. El panel usa el registro validado del listado porque
`GET /api/v1/event-programs/{id}` solo devuelve programas activos.

**Stack:** React 19, TypeScript, Chakra UI v3, TanStack Query, Vitest, Testing Library y Storybook.

## Contrato reconfirmado (2026-10-06)

| Operación                                                     | Uso                   |
| ------------------------------------------------------------- | --------------------- |
| `GET /api/v1/event-programs/{id}/collaborators`               | Consultar (Bearer)    |
| `POST /api/v1/event-programs/{id}/collaborators`              | Agregar persona       |
| `PATCH /api/v1/event-programs/{id}/collaborators/{userId}`    | Cambiar rol           |
| `DELETE /api/v1/event-programs/{id}/collaborators/{userId}`   | Retirar colaboración  |
| `POST /api/v1/event-programs/{id}/permissions`                | Otorgar permiso       |
| `DELETE /api/v1/event-programs/{id}/permissions/{permission}` | Revocar permiso local |

- La lectura y las mutaciones exigen `permission:grant` en el scope o el rol ADMIN.
- Un programa archivado no permite modificaciones; la lista se conserva consultable.
- El contrato no separa con códigos las causas de un `409`; los mensajes ya son conjuntos y
  localizados en `collaboratorFailure.ts`.

## Decisiones

- La experiencia vive en un panel de `/admin/programas`, no en una ruta de detalle.
- Cada tarjeta ofrece «Colaboradores», incluidos borradores y archivados.
- `readOnly` bloquea la modificación por el estado del programa; `canManage` conserva su
  significado de autorización. `readOnly` no concede acceso por sí mismo.
