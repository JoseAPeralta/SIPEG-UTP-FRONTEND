# Fase 7.3 - Bandeja personal de alertas - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Publicar la bandeja privada de alertas en `/perfil/alertas` como quinta seccion del area personal, con etiquetas en espanol, filtros, paginacion y enlaces solo a contextos operativos autorizados, y convertir el indicador global en su acceso.

**Architecture:** La bandeja reutiliza `useAlertsPage` (7.1) y el descubrimiento operativo `useOperationalAccess` (3.x). Un modelo puro traduce tipos y resuelve destinos; un hook compuesto `useAlertsInbox` une listado y autorizacion; una vista conectada controla filtros, pagina y estados; la pagina es delgada. Los destinos solo apuntan a rutas existentes y autorizadas (`/operaciones/programas/:id` y `/operaciones/actividades/:id`); propuestas y certificados quedan informativos porque su detalle no existe todavia.

**Tech Stack:** React 19, TypeScript 6, Chakra UI 3, TanStack Query 5, React Router 8, Vitest 5, Testing Library, Storybook 10.

**Decisiones registradas:**

- **Ruta personal confirmada por el usuario:** `/perfil/alertas` con «Mis alertas» como quinta seccion, despues de «Mis certificados».
- **Los enlaces no inferieren autorizacion:** una alerta recibida no prueba acceso; el destino se resuelve contra el descubrimiento de scopes, que ya filtra por permiso efectivo. Un `ACTIVITY` no hereda acceso de su programa padre.
- **Destinos solo a contextos operativos:** las rutas actuales de programa/actividad muestran permisos y colaboracion, por eso el rotulo es «Ver contexto del programa/actividad» y no «Ver programa».
- **El fallo de permisos no oculta la bandeja:** el listado se muestra sin enlaces y con aviso localizado y reintento.
- **`useAlertsPage` conserva la pagina anterior solo para la misma identidad.** Es una fuga de 7.1: `keepPreviousData` mostraba la bandeja de la cuenta anterior durante un cambio de sesion. Se corrige con una funcion de placeholder que compara el propietario de la clave anterior.

`alertNavigation.ts`:

```ts
import { operationalScopePath } from "@/features/collaboration/navigation";
import type { UserScope } from "@/features/collaboration";

import type { AlertTarget } from "./alert";

export type AlertDestination = { label: string; to: string };

/**
 * Resuelve el unico destino navegable de una alerta.
 *
 * Un objetivo recibido no autoriza: el scope debe aparecer en el descubrimiento, que ya exige un
 * permiso efectivo. Propuestas y certificados no tienen ruta de detalle todavia y quedan sin enlace.
 */
export function resolveAlertDestination(
  target: AlertTarget,
  scopes: readonly UserScope[],
): AlertDestination | null {
  if (target.kind === "PROPOSAL" || target.kind === "CERTIFICATE") {
    return null;
  }

  const type = target.kind === "EVENT_PROGRAM" ? "program" : "activity";
  const scope = scopes.find((item) => item.type === type && item.id === target.id);

  if (!scope) {
    return null;
  }

  return {
    label: type === "program" ? "Ver contexto del programa" : "Ver contexto de la actividad",
    to: operationalScopePath({ id: scope.id, type }),
  };
}
```

- [ ] **Step 3: Implementar el hook**

```ts
import { useOperationalAccess } from "@/features/collaboration/navigation";

import { resolveAlertDestination, type AlertDestination } from "../model/alertNavigation";
import type { AlertFilters } from "../model/alert";

import { useAlertsPage } from "./useAlertsPage";

/**
 * Bandeja privada con los destinos que la sesion puede abrir.
 *
 * El descubrimiento operativo es independiente del listado: si falla o aun carga, las alertas se
 * conservan visibles y solo se omiten los enlaces, porque un fallo de permisos no prueba que no haya
 * alertas.
 */
export function useAlertsInbox(filters: AlertFilters, page: number) {
  const listing = useAlertsPage(filters, page);
  const access = useOperationalAccess();

  const destinations = new Map<string, AlertDestination>();
  for (const alert of listing.page?.items ?? []) {
    const destination = resolveAlertDestination(alert.target, access.scopes);
    if (destination) destinations.set(alert.id, destination);
  }

  return {
    accessError: access.error,
    accessIsLoading: access.isLoading,
    destinations,
    error: listing.error,
    isFetching: listing.isFetching,
    isLoading: listing.isLoading,
    page: listing.page,
    refetch: listing.refetch,
    refetchAccess: access.refetch,
  };
}
```
