# Fase 2.3 Administracion De Carreras Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Permitir que ADMIN gestione carreras de facultad y globales sin vulnerar las restricciones contractuales de la carrera global OTROS.

**Architecture:** El modulo `features/careers` conserva la lectura publica y suma comandos autenticados al mismo puerto. Los adapters validan cada respuesta, los hooks invalidan solo las dos fronteras de cache de carreras y la vista administrativa traduce los errores HTTP a mensajes de producto.

**Tech Stack:** React 19, TypeScript 6, Chakra UI 3, TanStack Query 5, Vitest 5, Testing Library y Storybook 10.

---

## Contrato verificado

- `GET /api/v1/careers` es publico, paginado y permite `unitId` y `q`.
- `POST /api/v1/careers`, `PATCH /api/v1/careers/{id}` y `DELETE /api/v1/careers/{id}` requieren `bearerAuth` y rol `ADMIN`.
- Crear exige `name` y `code`; `description` y `unitId` son opcionales y `unitId: null` crea una carrera global.
- Solo una `FACULTY` activa puede ser unidad de una carrera. Los codigos son unicos sin distinguir mayusculas.
- OTROS no puede cambiar codigo, dejar de ser global ni eliminarse. Una carrera con usuarios no puede cambiar unidad ni eliminarse.
