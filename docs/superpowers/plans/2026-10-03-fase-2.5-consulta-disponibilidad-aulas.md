# Fase 2.5 Consulta De Disponibilidad De Aulas Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Entregar un selector reutilizable que consulta aulas disponibles para una necesidad de actividad sin calcular ni persistir disponibilidad en el cliente.

**Architecture:** `features/classrooms` amplía el puerto existente con una lectura pública y no paginada para disponibilidad. Los adapters validan criterios y envelopes, el mock reproduce las reglas contractuales de ventana y reserva, TanStack Query conserva resultados efímeros por criterios enviados, y un selector controlado recibe los criterios y la selección del futuro formulario de actividades.

**Tech Stack:** React 19, TypeScript 6, Chakra UI 3, TanStack Query 5, Vitest 5, Testing Library y Storybook 10.

---

## Contrato verificado

Consultado el 2026-10-03 contra el backend vivo:

| Operacion                          | Auth    | Parametros                                                                  | Respuesta            | Errores |
| ---------------------------------- | ------- | --------------------------------------------------------------------------- | -------------------- | ------- |
| `GET /api/v1/classrooms/available` | publica | `date`, `startTime`, `endTime`; `minCapacity`, `type`, `amenity` opcionales | `ClassroomSummary[]` | `400`   |

- El backend incluye solo aulas activas cuya ventana semanal cubre todo el intervalo de la fecha.
- Actividades `SCHEDULED` y `ONGOING` reservan el aula; `DRAFT`, `COMPLETED` y `CANCELLED` no la bloquean.
- El contrato admite una unica `amenity`; no se implementa una interseccion cliente de varias amenidades.
- La consulta no lleva Bearer y no se agrega a `PERSISTED_QUERY_KEY_ROOTS`.

## Decisiones de alcance

- No se crea ruta temporal: el componente se valida aislado con Vitest y Storybook y se integrará al formulario de actividades en 5.5.
- El usuario pulsa `Consultar aulas`; editar criterios no inicia solicitudes.
- Si una nueva consulta ya no contiene el aula seleccionada, se conserva el valor controlado y se anuncia que debe elegirse otra. Nunca se pierde una selección sin aviso.
- La actividad que edita su propia reserva queda fuera: el contrato no recibe `activityId` para excluirla. Se reconfirmará antes de 5.5.
