# Fase 7.2 - Indicador global de alertas - Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Mostrar en la navegacion principal el conteo de alertas sin leer de la identidad autenticada, con nombre accesible, sin persistencia y sin exponer errores del backend.

**Architecture:** Un hook privado `useUnreadAlertsCount` reutiliza la clave de pagina de 7.1 con `filters = { isRead: false }, page = 1` y proyecta `total` con `select`. Un componente conectado `UnreadAlertsIndicator` traduce el estado a cuatro presentaciones (carga, cero, conteo, fallo) y se carga de forma diferida desde `AppMenu` a traves de un entrypoint enfocado `@/features/alerts/navigation`, igual que `OperationalMenuLink`. La fase es informativa: no crea ruta ni enlace; 7.3 convierte el indicador en acceso a la bandeja.

**Tech Stack:** React 19, TypeScript 6, Chakra UI 3, TanStack Query 5, Zustand 5, Vitest 5, Testing Library, Storybook 10.

**Decisiones registradas:**

- **Sin `role="status"`:** la region global haria que `getByRole("status")` dejara de ser unico en todas las pantallas autenticadas (`App.accountJourney.test.tsx:275` ya lo usa para el aviso de perfil). El anuncio se logra con `aria-live="polite" aria-atomic="true"` y un texto alternativo visualmente oculto, con la forma corta visible marcada `aria-hidden`.
- **Sin placeholder entre identidades:** el conteo jamas conserva el valor de la identidad anterior mientras carga el nuevo.
- **Conteo por `total`, no por `items.length`:** una bandeja paginada no puede subcontar.
- **Sin persistencia:** `alertsPage` no pertenece a `PERSISTED_QUERY_KEY_ROOTS`.

- [ ] **Step 3: Implementar el hook**

```ts
import { useQuery } from "@tanstack/react-query";

import { useAppAdapters } from "@/app/adapters";
import { queryKeys } from "@/app/query";
import { useSessionStore } from "@/store/session";

import type { AlertFilters } from "../model/alert";

const UNREAD_FILTERS: AlertFilters = { isRead: false };

/**
 * Conteo de alertas sin leer de la sesion.
 *
 * Se apoya en la primera pagina filtrada por `isRead=false` y proyecta `total`, porque contar
 * `items` subestimaria cualquier bandeja con mas de una pagina. La clave es la misma que usara la
 * bandeja de 7.3, se liga al `userId` y nunca se persiste. Sin sesion o durante la restauracion no
 * se consulta; al cambiar de identidad no hay dato previo que mostrar porque la clave cambia.
 */
export function useUnreadAlertsCount() {
  const { alerts } = useAppAdapters();
  const status = useSessionStore((state) => state.status);
  const userId = useSessionStore((state) => state.currentUser?.id);
  const canLoad = status === "authenticated" && userId !== undefined;

  const query = useQuery({
    enabled: canLoad,
    queryFn: () => alerts.loadAlertsPage(UNREAD_FILTERS, 1),
    queryKey: queryKeys.alertsPage(userId ?? "anonymous", UNREAD_FILTERS, 1),
    select: (page) => page.total,
  });

  return {
    count: canLoad ? (query.data ?? null) : null,
    error: query.error,
    isFetching: query.isFetching,
    isLoading: canLoad && query.isLoading,
  };
}
```

- [ ] **Step 3: Implementar el componente**

```tsx
import { Box, VisuallyHidden } from "@chakra-ui/react";

import { useUnreadAlertsCount } from "../hooks/useUnreadAlertsCount";

/**
 * Indicador informativo del conteo de alertas sin leer.
 *
 * En 7.2 no navega: la bandeja llega en 7.3. La forma corta visible es decorativa y el texto
 * alternativo viaja visualmente oculto dentro de una region `aria-live` discreta, de modo que cada
 * cambio de conteo se anuncie sin mover el foco y sin convertir cada pantalla autenticada en un
 * segundo `role="status"`. Un fallo nunca se presenta como cero.
 */
export function UnreadAlertsIndicator() {
  const { count, error, isLoading } = useUnreadAlertsCount();

  const hasSessionData = count !== null || isLoading || error !== null;

  if (!hasSessionData) {
    return null;
  }

  const display = isLoading ? "…" : error ? "—" : String(count);
  const summary = isLoading
    ? "Cargando alertas"
    : error
      ? "No se pudo actualizar el conteo de alertas"
      : count === 0
        ? "No tienes alertas sin leer"
        : count === 1
          ? "Tienes 1 alerta sin leer"
          : `Tienes ${count} alertas sin leer`;

  return (
    <Box
      alignItems="center"
      aria-atomic="true"
      aria-live="polite"
      bg="surface.raised"
      borderColor="border.subtle"
      borderWidth="1px"
      color="text.default"
      display="inline-flex"
      fontSize="sm"
      fontWeight="800"
      px={4}
      py={2.5}
      rounded="full"
    >
      <VisuallyHidden>{summary}</VisuallyHidden>
      <Box aria-hidden="true" as="span">
        Alertas · {display}
      </Box>
    </Box>
  );
}
```

Donde `hasSessionData` distingue "sin sesion" (ni dato, ni carga, ni fallo) de los cuatro estados
visibles: carga, cero, conteo y fallo. No hay un booleano de sesion en el hook porque el componente
solo debe dibujar cuando tiene algo que decir.
