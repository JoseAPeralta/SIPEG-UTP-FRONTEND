# Fase 3.1 - Separacion de usuarios del read model

> **For agentic workers:** REQUIRED SUB-SKILL: Use `executing-plans` to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrar `GET /api/v1/admin/users` mediante un puerto, mappers, adapter mock/API, claves Query y hook propios, y retirar `users` de `OperationsReadModel` sin cambiar la pantalla actual.

**Architecture:** `features/users` recibe un `UsersAdapter` con lectura administrativa paginada que en 3.1 recorre todas las paginas con `limit=50` y conserva la metadata para 3.2. El mapper valida cada envelope y cada `AdminUser` (incluidas las referencias embebidas `unit` y `career`). `useUsers` vive en la frontera administrativa ligada al `userId`, nunca al token, y no se persiste. Los consumidores (`useUsersOverview` y `useCertificatesOverview`) dejan de leer el agregado.

**Tech Stack:** React 19, TypeScript, TanStack Query 5, Vitest, adapters mock/API.

---

## Contrato verificado (backend vivo, 2026-10-04)

- `GET /api/v1/admin/users` con `bearerAuth`, exclusivo de `ADMIN`.
- Parametros: `page` (default 1), `limit` (default 20, maximo 50), `globalRole` (`USER|ADMIN`), `isActive` (`true|false`), `unitId`, `careerId`, `q` (1..200).
- Respuesta `PaginatedUsers`: `{ items, page, limit, total, totalPages }` dentro del envelope estandar.
- `AdminUser`: `id`, `firstName`, `lastName`, `identificationNumber`, `email`, `globalRole`, `isActive`, `unit: OrganizationReference|null`, `career: OrganizationReference|null`; todos requeridos.
- `OrganizationReference`: `{ id, name, code }` requeridos.
- Errores documentados: `400`, `401`, `403`.
