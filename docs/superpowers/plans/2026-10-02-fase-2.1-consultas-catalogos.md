# Fase 2.1 Consultas De Catalogos Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Separar las consultas de unidades organizacionales, carreras y aulas en puertos, adapters, mappers, hooks y query keys propios sin cambiar la experiencia visual ni adelantar el CRUD de las fases 2.2 a 2.5.

**Architecture:** Los tres recursos usan sus operaciones GET publicas con `auth: { mode: "none" }`; la frontera publica o administrativa se expresa mediante query keys separadas y ligadas a identidad cuando corresponde. `useActivityCatalog` y `useRegistrationCatalog` permanecen como read models compuestos para evitar cambios en páginas y formularios, mientras carreras sale del agregado legado `OperationsReadModel`.

**Tech Stack:** React 19, TypeScript 6, TanStack Query 5, Vitest 5, Testing Library y adapters HTTP validados contra OpenAPI.

---

## Contrato Verificado

- `GET /api/v1/organizational-units`: publico, paginado, filtros `type`, `isActive` y `q`.
- `GET /api/v1/careers`: publico, paginado, filtros `unitId` y `q`.
- `GET /api/v1/classrooms`: publico, paginado, filtros `type`, `minCapacity`, `amenity` e `isActive`.
- `GET /api/v1/organizational-units/{id}` y `GET /api/v1/classrooms/{id}` existen, pero quedan fuera de 2.1.
- Los listados permiten `limit=50`; los adapters de 2.1 recorren todas las páginas para conservar el comportamiento actual.
- `pnpm run api:mocks-check` parte en verde con 83 verificaciones sobre 7 operaciones.

## Contratos Objetivo

```ts
export type CatalogAccess = "administrative" | "public";

export type OrganizationalUnitsAdapter = {

export type ActivityCatalogAdapter = {
  loadCatalog: (

};
```
